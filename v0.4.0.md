# v0.4.0 — Armas com Física Própria

> **Status:** Planejado
> **Fase:** 3 — Cada Arma Diferente de Verdade
> **Depende de:** [v0.3.0](./v0.3.0.md)
> **Objetivo:** Implementar 6 armas com física, comportamento e efeitos distintos. Cada arma deve se sentir diferente na mão.

---

## 1. Resumo

Esta versão expande o sistema de projéteis para suportar múltiplas armas com física própria. O jogador pode trocar armas no painel de debug. Cada arma tem peso, influência de vento, área de impacto, poder de escavação e tipo de dano diferentes. O `WeaponSystem` é a fonte de verdade para definição das armas.

---

## 2. Objetivo da Entrega

Implementar as 6 armas mínimas com física e comportamento distintos:

1. **Canhão** — pesado, pouca influência do vento, grande área, forte escavação.
2. **Arco Longo** — leve, alta influência do vento, bom alcance, trajetória limpa.
3. **TNT** — muito pesado, cai quase em linha reta, grande explosão e destruição.
4. **Boomerangue** — trajetória curva (vai e volta), alta influência do vento.
5. **Livro de Gelo** — projétil mágico, trajetória suave, área menor, tipo mágico.
6. **Poções** — arco moderado, efeito de respingo ao impactar.

---

## 3. Escopo

### Dentro do escopo

- `WeaponSystem` (TypeScript puro) com `WeaponDefinition` para cada arma.
- Física de projétil parametrizada por arma (gravity scale, wind influence, etc.).
- Trajetória curva para o Boomerangue (ângulo virando ao longo do tempo).
- Área de impacto variável por arma.
- Poder de escavação por arma (raio de explosão no terreno).
- Tipo de dano: físico, mágico ou misto.
- Seletor de arma no painel de debug.
- Efeito visual distinto por arma (cor, forma do sprite placeholder).
- Som placeholder por arma (ao menos diferente em pitch/tom).

### Fora do escopo

- Efeitos rúnicos das armas (v0.6.0).
- Requisitos de atributos (v0.5.0).
- Animações de personagem por arma.
- Sistema de munição/cooldown.

## 4. Interface de Contrato

```ts
// weapon-definition.ts
export interface WeaponDefinition {
  id: string;
  name: string;
  hands: 1 | 2;
  damageType: 'physical' | 'magical' | 'mixed';
  baseDamage: number;
  physicsProfile: ProjectilePhysicsProfile;
  impactRadius: number;     // raio de dano
  excavationRadius: number; // raio de destruição de terreno
  runeEffect?: string;      // vazio nesta versão, usado na v0.6.0
}

export interface ProjectilePhysicsProfile {
  gravityScale: number;    // 1.0 = normal, 2.0 = cai rápido
  windInfluence: number;   // 0.0 = imune, 1.0 = muito influenciado
  initialSpeed: number;    // pixels/s na velocidade base
  boomerang?: boolean;     // se true, reverte direção após apex
  bounces?: number;        // número de quiques (padrão 0)
}
```

## 6. Comportamento Especial do Boomerangue

```ts
// A trajetória do boomerangue reverte no apex (ponto mais alto)
// ou após N pixels horizontais:

if (projectile.weapon.physicsProfile.boomerang) {
  const elapsed = currentTime - projectile.launchTime;
  if (elapsed > BOOMERANG_REVERSAL_TIME) {
    projectile.velocityX *= -0.8; // inverte e perde velocidade
  }
}
```

---

## 7. Integração com TerrainEngine

Ao impactar:
- Calcular `explosionRadius = weapon.excavationRadius`.
- Chamar `terrainEngine.explode(impactX, impactY, excavationRadius)`.
- Aplicar dano em `impactRadius` (pode ser maior que excavation).

## 9. Critérios de Aceite

- [ ] Cada arma tem trajetória visualmente distinta.
- [ ] Canhão cai mais rápido e é menos afetado pelo vento que o Arco.
- [ ] TNT cria explosão maior que as outras armas.
- [ ] Boomerangue reverte direção visivelmente.
- [ ] Livro de Gelo tem projétil de cor diferente (azul/magenta).
- [ ] Raio de escavação varia visivelmente entre Canhão e TNT.
- [ ] Seletor de arma no debug funciona sem reiniciar a cena.
- [ ] IA usa a arma selecionada para o seu turno.

## 11. Riscos

| Risco | Mitigação |
|---|---|
| Boomerangue com física instável | Usar curva de Bezier simples em vez de física real |
| Parâmetros de física desequilibrados | Ajustar via debug, documentar valores no WeaponDefinition |
| Sons placeholder muito incômodos | Usar variação de pitch em um único arquivo base |
