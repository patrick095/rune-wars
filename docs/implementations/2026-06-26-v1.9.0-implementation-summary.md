# v1.9.0 - Refatoracao do Sistema de Assets e Animacoes

## Objetivo

Implementar o pipeline visual modular descrito em `docs/implementations/2026-06-26-v1.9.0-spec.md`, com Asset Manifest v2, anchors por frame, perfis visuais de armas e um renderer Phaser compartilhado por PvP, academia e dungeon, preservando gameplay existente.

## Implementacao

- Evoluido `asset-catalog.json` para `schemaVersion: 2`, com render order `back/body/armor/face/hair/helmet/weapon/cape/wing/effects`, racas obrigatorias `human`, `elf`, `celestial`, `demonoid`, `beast`, e `dwarf` como legado.
- Criados contratos TypeScript para manifest v2, anchors, animacoes canonicas, camadas, perfis visuais de armas e estados de arma.
- Criados manifests v2 de personagem e `anchors.json` para as racas obrigatorias e para `dwarf`.
- Criados placeholders tecnicos para os 33 frames canonicos por raca e por camada, a partir dos assets atuais `idle_0` e `battle_0`.
- Criados manifests v2 e estados `weapon_idle`, `weapon_ready`, `weapon_aim`, `weapon_fire` para canhao, arco, TNT, granada, pocao, boomerang, livro e cajado.
- Implementado fallback de `weapon_fire` para `weapon_aim` quando a arte distinta nao existe.
- Implementado `AnchorResolver`, `ModularCharacterAnimator` e `ModularCharacterRenderer`.
- Migrado `BattleScene` para renderizar player e AI pelo renderer modular, mantendo retangulos/proxies de gameplay para camera, colisao, queda e fisica atual.
- Migradas `AcademyScene` e `DungeonScene` para usar o mesmo renderer modular nos players humanoides.
- Adicionado `tools/validate-rune-wars-assets.mjs` para validar catalogo, manifests, frames, anchors, perfis visuais, projeteis, efeitos e dimensoes PNG.

## Decisoes

- Usar placeholders tecnicos explicitos porque o repo ainda nao possui arte final de 33 frames por raca.
- Manter `dwarf` como fallback legado carregavel, fora do pacote obrigatorio v1.9.0.
- Preservar fisica, dano, vento, turnos, IA e terreno; anchors foram usados para visual e alinhamento, nao para reescrever gameplay.
- Manter proxies de gameplay existentes em `BattleScene` e trocar somente o renderer visual, reduzindo risco sobre camera/colisao.
- Usar o estilo Rune Wars 2D HD cartoon fantasy com leitura rapida e efeitos contidos.

## Bugs

- Importante: a arte final de 33 frames por raca ainda nao existe. O contrato e o runtime estao prontos, mas os frames atuais sao placeholders tecnicos derivados dos assets existentes.
- Baixo: `npm run build` passa, mas ainda emite warnings de budget inicial, budget de `pvp-room.component.scss` e CommonJS do Phaser.
