# Spec de Implementação — v1.4.0

> Bugs, Mapas, Texturas, Modificadores de Tiro e Arquitetura Single-Screen

---

## 1. Resumo

Corrigir bugs críticos de gameplay (explosão lenta, tiro durante queda, spawn inválido, movimentação em desnível), melhorar a qualidade visual dos mapas (tamanho, complexidade, texturas PNG, backgrounds), adicionar um sistema de modificadores de tiro com dois docks visuais, implementar o lobby PvP com salas, converter a navegação para single-screen sem router entre telas do jogo, definir resolução máxima com moldura, e corrigir bloqueio de cliques em modais.

---

## 2. Pedido Original

**Lote A — Bugs e melhorias de gameplay:**

1. Tiro bate no terreno e demora a explodir — deve ser instantâneo
2. Player consegue atirar enquanto cai, mesmo abaixo do nível mais baixo do mapa — deve ter uma linha de morte
3. Abaixo do indicador de vento, mostrar o vento e força do último turno de quem está na vez
4. Alguns spawn points iniciam o player em queda imediata/morte
5. Mapas pequenos — quero pelo menos 1.5x maior horizontal e 2x maior vertical
6. Mais complexidade nos mapas
7. Mapas devem usar texturas PNG, ter background visual rico (referência: imagem de ilhas flutuantes enviada)
8. Movimentação em desnível não funciona corretamente
9. Dois docks no battle scene/playground: um para consumíveis, um para modificadores de tiro (+1, x3, +100% dano, +100% escavar)

**Lote B — Arquitetura, navegação e UX:**

10. PvP Arena: ao entrar vai para lobby com lista de salas em andamento, criar sala, dentro da sala escolhe CPU ou players reais
11. Menu debug só aparece ao apertar tecla "o" e pode ser ocultado (fase de testes, sem restrição de acesso)
12. Se a tela/monitor for maior que a resolução máxima do jogo, deve aparecer uma moldura separando o jogo; todas as partidas devem respeitar o mesmo tamanho
13. Tudo em uma tela só — sem navegação entre páginas, sensação de jogo
14. Modais devem desativar cliques no que está atrás

---

## 3. Problema a Resolver

**Gameplay:** Bugs que quebram a experiência competitiva (explosão com delay, tiro no void) e limitações visuais que diminuem o apelo (mapas pequenos e sem personalidade).

**Arquitetura:** O app usa Angular Router entre páginas separadas, o que quebra a sensação de jogo (URL muda, tela pisca em branco na navegação). A ausência de bloqueio de cliques em modais e a falta de resolução fixa fazem o jogo parecer um site. O menu debug está sempre visível.

---

## 4. Objetivo da Implementação

- Zero bugs de física de projétil e queda
- Mapas 2x mais ricos visualmente e espacialmente
- Sistema de modificadores de tiro funcional com docks nativos
- Lobby PvP com salas (CPU ou player real)
- App funciona como jogo: tela única, sem transições de página
- Resolução fixa com moldura para monitores grandes
- Modais bloqueiam cliques no que está atrás
- Debug visível apenas via tecla "O"

## 6. Pesquisa e Referências

### O que foi pesquisado

- Padrões de detecção de colisão em tempo real para projéteis em Phaser 3
- Sistemas de "death zone" em jogos artillery (Scorched Earth, Worms Armageddon)
- Técnicas de tileset para jogos 2D side-scroller
- Design de floating island maps (Terraria, Worms W.M.D, imagem fornecida)
- Padrões de HUD de informação de turno em artillery games
- Single-page game architectures em Angular/React (estado global vs router)
- Letterbox / game frame em web games

### Pontos relevantes encontrados

- Worms resolve explosão lenta com detecção frame-a-frame, não path pré-calculado
- Death lines ficam em `worldHeight * 1.1` (margem abaixo do mapa)
- Floating islands precisam de spawn points em plataformas específicas
- Single-screen games como Genshin/FFXIV usam estado interno + fade entre "telas" sem URL change
- Letterbox via CSS `aspect-ratio` + `min()` é a solução mais clean para resolution cap

### O que será aproveitado

- Detecção de terreno mid-animation (early-exit no `animateAlongPath`)
- Death zone baseada em threshold de Y
- Spawn validation via `getFloorBelow`
- CSS letterbox para game frame
- EventBus já existente como base para o GameNavigatorService

### O que foi descartado

- Reescrever physics engine — só a animação é lenta
- Usar engine de física real (Matter.js) — over-engineering
- Geração procedural de mapas — manter JSON manual
- Eliminar router completamente — login/register/character-select continuam como rotas

## 10. Regras de Negócio

### Modificadores de Tiro

| ID | Nome | Efeito |
|---|---|---|
| `shot_plus1` | +1 Tiro | 1 tiro idêntico com delay 700ms |
| `shot_x3` | x3 Tiros | 3 simultâneos: angle-5, angle, angle+5 |
| `shot_damage_2x` | +100% Dano | `baseDamage × 2` |
| `shot_dig_2x` | +100% Escavar | `excavationRadius × 2` |

- **O player pode escolher apenas 1 modificador por turno** — ao selecionar um novo, o anterior é automaticamente descartado
- Modificador consumido ao atirar (uso único por turno)
- Ao iniciar o turno do player, qualquer modificador ativo do turno anterior é removido

### Death Line

- `sprite.y > worldHeight * 1.05` → morte imediata
- `playerFall.isFalling === true` → `startChargingPower()` ignorado

### Spawn Points

- Spawn válido = `getFloorBelow(x, y)` retorna valor dentro de 3 células abaixo
- Spawn inválido → descartar, tentar próximo da lista

### Salas PvP

- Sala criada com `playerCount = 1` (criador)
- Sala com `playerCount = 0` por 30s → deletada pelo backend
- Sala CPU não ocupa slot no servidor (apenas estado local)
- Máximo 2 jogadores por sala (1v1)

### Fluxo PvP Lobby

```

     └─ PvpLobbyComponent (overlay)
         ├─ Lista de salas (polling 5s)
         ├─ [Criar Sala] → PvpRoomComponent (nova sala)

 ├─ [Jogar vs CPU] → lança BattleScene (modo pvp, AI ativa) → volta ao lobby no fim

Batalha encerrada
 └─ ResultOverlay mostra vitória/derrota
     └─ [Voltar ao Lobby] ou [Hub]
```

```
Turno do jogador
 └─ Dock "Modificadores" visível
     └─ Clica modificador → ativo (borda dourada)

             └─ Slot vazio
```


#### Fix A8 — ShotModifierSystem

**Novo arquivo:** `src/app/shared/game-core/shot-modifier-system.ts`

```ts
export type ShotModifierType = 'shot_plus1' | 'shot_x3' | 'shot_damage_2x' | 'shot_dig_2x';

export class ShotModifierSystem {
  private active: ShotModifierType | null = null;  // apenas 1 por turno

  activate(id: ShotModifierType): void {
    // selecionar novo desmarca o anterior automaticamente
    this.active = (this.active === id) ? null : id;
  }

  getActive(): ShotModifierType | null { return this.active; }
  isActive(id: ShotModifierType): boolean { return this.active === id; }
  consumeAll(): void { this.active = null; }  // chamado após atirar e ao início do turno

  resolve(baseAngle: number, baseForce: number, weapon: WeaponDefinition): ResolvedShots {
    const mod = this.active;
    const damage = (mod === 'shot_damage_2x') ? weapon.baseDamage * 2 : weapon.baseDamage;
    const radius = (mod === 'shot_dig_2x')   ? weapon.excavationRadius * 2 : weapon.excavationRadius;

    const shots: ShotConfig[] = [{ angle: baseAngle, force: baseForce, damage, radius }];

    if (mod === 'shot_x3') {
      shots.push({ angle: baseAngle - 5, force: baseForce, damage, radius });
      shots.push({ angle: baseAngle + 5, force: baseForce, damage, radius });
    }

    const delayedShots: ShotConfig[] = (mod === 'shot_plus1')
      ? [{ angle: baseAngle, force: baseForce, damage, radius, delayMs: 700 }]
      : [];

    return { shots, delayedShots };
  }
}
```

Em `battle.scene.ts`, substituir `firePlayerShot` para usar `shotModifierSystem.resolve()` e disparar múltiplos projéteis conforme resultado.

#### Feat B3 — Modal Click Blocking

**Dois mecanismos combinados:**

1. **CSS automático:** Cada overlay/modal tem `position: absolute; inset: 0; z-index: 100+`. Elementos com z-index menor automaticamente não recebem eventos de pointer.

2. **Canvas pointer-events:** `AppComponent` observa `navigator.screen`:
```ts
effect(() => {
  const screen = this.navigator.screen();
  const canvas = document.getElementById('hub-canvas');
  if (canvas) {
    canvas.style.pointerEvents = (screen === 'hub') ? '' : 'none';
  }
});
```

3. **Backdrop em modais flutuantes:**
```html
<!-- quando modal character está ativo -->
<div class="modal-backdrop" (click)="closeModal()"></div>
<app-character />
```
```scss
.modal-backdrop {
  position: absolute; inset: 0;
  z-index: 199; background: rgba(0,0,0,0.6);
}
app-character { z-index: 200; position: absolute; }
```

## 19. Tratamento de Erros

| Situação | Comportamento |
|---|---|
| Nenhum spawn válido | Fallback: 10% e 90% horizontal, primeiro chão abaixo do centro |
| PNG de terrain não carregado | Tile programático (fallback automático) |
| x3 tiro fora dos bounds | Projétil termina ao sair dos bounds do mundo |
| Sala não encontrada ao entrar | Toast de erro + volta ao lobby |
| Backend PvP fora do ar | Modo CPU sempre disponível como fallback |
| `game-frame` não encontrado | Phaser usa `document.body` como fallback |
| Modal aberto + tecla ESC | Fecha modal, não fecha o jogo |
