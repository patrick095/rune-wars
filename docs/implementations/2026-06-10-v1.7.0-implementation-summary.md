# Resumo Final — v1.7.0: Inventário Real + Cofre + Admin Panel + Sala PvP Redesenhada

## Objetivo
Implementar as quatro grandes entregas da versão 1.7.0:
1. Inventário funcional com dados reais (ITEM_CATALOG, equip/unequip via backend)
2. Cofre/baú funcional (overlay Angular com DnD entre inventário e cofre)
3. Admin Panel (tecla "I" no Hub abre painel para admin inspecionar/editar inventários)
4. Sala PvP redesenhada (4 slots de equipe, carrossel de mapa, modos, consumíveis persistentes, botão PRONTO)
5. Bônus: modo LIVRE com 1 jogador inicia partida vs CPU

## O que foi implementado

### Backend

**Auth + Admin**
- `User.is_admin: boolean` adicionado à entity (synchronize aplica no banco)
- JWT payload inclui `isAdmin` após login
- `AdminModule` com `AdminGuard`, `AdminController` (4 endpoints) e `AdminService`
- Endpoints: `GET /admin/characters`, `GET /admin/characters/:id/inventory`, `POST /admin/characters/:id/inventory/add`, `POST /admin/characters/:id/consumables/add`

**Consumable Inventory**
- Entity `CharacterConsumable` (`character_consumable` table)
- `ConsumableInventoryModule` com 3 endpoints: `GET/POST .../consumables`, `POST .../consumables/use`, `POST .../consumables/add`
- Ownership verificado via `validateOwnership(characterId, userId)` com query ao Character

**PvP Room**
- `PvpRoom` entity estendida com `slots: SlotState[]` (jsonb), `mode`, `map_slug`, `vs_cpu`
- 3 novos endpoints: `POST .../slots/:index/close`, `POST .../slots/:index/kick`, `POST .../ready`
- Endpoint `ready` aceita `vs_cpu: boolean` — se `true` em modo `free` com 1 jogador, marca sala para partida solo vs CPU

**Inventory**
- Novo endpoint `POST /characters/:id/inventory/move` para reorganização (reordenação client-side, sem `sort_order` no DB)

**Migrations (referência)**
- `1749500000000-add-is-admin-to-user.ts`
- `1749500001000-create-character-consumable.ts`
- `1749500002000-add-pvp-room-slots-mode-mapslug.ts`

### Frontend

**ITEM_CATALOG**
- `shared/game-core/item-catalog.ts` — 36 itens catalogados em 8 categorias (weapon, armor, head, legs, accessory, secondary, consumable, material)
- `getItemDefinition(id)` com fallback para "Item Desconhecido"

**Inventário**
- `InventoryService` reescrito: endpoints corretos, resolução de itens via ITEM_CATALOG
- `CharacterComponent`: `loadInventory()` separa equipados/não-equipados, `onEquip/onUnequip` chamam backend
- `EquipmentSlotsComponent.onDrop()` emite evento `itemDropped`

**Cofre**
- `VaultScreenComponent` (standalone): duas colunas com forkJoin paralelo, DnD deposit/withdraw, modal de taxa (100g), botão fechar
- `GameScreen: 'vault'` registrado no `GameNavigatorService`
- `AppComponent` renderiza o vault condicionalmente

**Consumable Inventory Service**
- `ConsumableInventoryService` com 3 métodos HTTP e `CONSUMABLE_CATALOG` (5 consumíveis)

**Admin Panel**
- `AdminInventoryPanelComponent` (standalone): busca com debounce, grid de inventário, formulários de adição de item e consumível
- `HubComponent`: `@HostListener('document:keydown')` — tecla "I" abre painel somente para admins
- `AuthService` ganhou `getDecodedToken()` e `isAdmin()` via decode JWT com `atob`

**PvP Room Redesign**
- Completamente reescrito: 4 slots de equipe, carrossel de 5 mapas com thumbnail, 3 modos de batalha
- 5 slots de consumíveis selecionados (repetíveis, borda laranja)
- Inventário de consumíveis real via `ConsumableInventoryService`
- Botão **PRONTO** (chama `setReady`) ou **JOGAR VS CPU** (modo LIVRE solo)
- SCSS: background com overlay escuro, bordas douradas, slot líder em roxo, botão PRONTO laranja/dourado

## Decisões tomadas
- TypeORM `synchronize: true` — entities drive DB schema; migrations são referência/documentação
- `ITEM_CATALOG` como TypeScript estático (zero migrations para novos itens)
- Cofre e Admin Panel como overlays Angular seguindo padrão do projeto
- `is_admin` como boolean simples no User (MVP — RBAC seria over-engineering)
- `character_consumable` como tabela separada para controle de estoque real
- 5 slots de consumíveis independentes e repetíveis na sala PvP
- Ownership de consumíveis verificado via `validateOwnership(characterId, userId)` (não via JWT)
- `AdminService.addConsumable()` usa Character repository diretamente
- Modo LIVRE solo: botão "JOGAR VS CPU" → `setReady` com `vs_cpu: true`
- Background PvP via `[style.backgroundImage]` inline (bundler Angular não resolve `url()` em SCSS)
- Admin busca client-side (endpoint `/admin/characters` não tem parâmetro de busca)

## Observações para manutenção
- O projeto usa `synchronize: true` no TypeORM — nunca usar em produção. Migrar para `synchronize: false` + migrations explícitas antes do deploy.
- `AdminService.addConsumable()` faz upsert manual (find → update/insert). Se performance for problema, migrar para `INSERT ... ON CONFLICT DO UPDATE`.
- `AuthService.isAdmin()` decoda JWT via `atob` no frontend — funciona mas não é criptograficamente seguro para verificação crítica. Backend valida via `AdminGuard` em todos os endpoints críticos.
- `joinRoom` (BUG-011-03) precisa ser corrigido para popular `slots` ao entrar na sala (v1.7.1).
