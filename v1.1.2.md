# v1.1.2 - Hub Modular, Estradas Jogaveis e Personagens Animados

> Status: Implementado parcialmente
> Base visual: estilo aprovado do `hub_forest_painted.png`
> Objetivo: separar arte de fundo, POIs clicaveis e locomocao do personagem para aumentar imersao sem bloquear expansoes futuras.

## 1. Decisao de Arte

O estilo visual aprovado e o mesmo da arte pintada gerada na v1.1.1:

- 2D HD cartoon fantasy premium.
- Pintura rasterizada, nao SVG flat.
- Camera 3/4 superior, com leitura de MMORPG.
- Cores vivas, floresta magica, montanhas, cachoeiras, ruinas, caminhos de pedra e pads.
- HUD Angular por cima do Phaser.

Esse estilo deve ser mantido em todos os assets novos do hub.

## 2. Separacao Obrigatoria de Assets

O hub nao deve voltar a usar uma imagem unica contendo fundo + predios clicaveis.

Camadas corretas:

1. `backgrounds/hub_forest_painted.png`
   - Apenas floresta, estradas, montanhas, ruinas, paisagem, pads e atmosfera.
   - Nao deve conter predios principais clicaveis, personagem, labels ou HUD.
2. `poi-raster/*.png`
   - Um arquivo por local clicavel.
   - Deve ser renderizado pelo Phaser como sprite separado.
   - Deve permitir hover, tint, sombra, pulso, click feedback e futura animacao.
3. Labels
   - Devem continuar no Phaser como placas pretas/douradas.
4. HUD
   - Deve continuar no Angular.

## 4. Estradas e Movimento no Hub

O personagem nao deve andar livremente pelo mapa.

Regra:

- O movimento no hub e permitido somente em estradas e pracas mapeadas.
- O mapa visual e o mapa logico precisam estar alinhados.
- A estrada ate a Arena PvP deve ser continua e clara.
- Se o usuario tentar sair da estrada, o movimento deve ser bloqueado suavemente.

Implementacao atual:

- `HubScene` possui `HUB_ROADS`, com segmentos de estrada.
- `HubScene` possui `HUB_WALK_ZONES`, com areas elipticas para pracas/pads.
- `movePlayer()` testa a proxima posicao antes de mover.
- `isWalkable()` valida se o ponto esta em uma zona ou perto de um segmento de estrada.

Regra de manutencao:

- Sempre que o background do hub mudar, atualizar tambem `HUB_ROADS` e `HUB_WALK_ZONES`.
- Futuramente, substituir segmentos manuais por um `walkmask` rasterizado, onde pixels claros indicam area caminhavel.

## 5. Estrategia de Personagens

Personagens devem ser produzidos como spritesheets, nao como imagens soltas sem padrao.

Direcoes obrigatorias:

- `front`: olhando para baixo/frente da tela, usado no hub ao andar para baixo.
- `back`: olhando para cima/costas, usado no hub ao andar para cima.
- `left`: usado em combate e hub lateral.
- `right`: espelhamento ou sprite proprio para direita.

Animacoes obrigatorias por personagem:

- `idle_front`
- `idle_back`
- `idle_left`
- `idle_right`
- `walk_front`
- `walk_back`
- `walk_left`
- `walk_right`
- `jump`
- `fall`
- `climb`
- `aim`
- `shoot`
- `hit`
- `knockback`
- `defeat`

Animacoes opcionais futuras:

- `cast`
- `victory`
- `emote`
- `mount_idle`
- `mount_walk`

## 6. Contrato de Sprite Sheet

Formato recomendado:

- PNG com alpha.
- Tamanho padrao inicial: `128x128` por frame para personagens chibi.
- Todos os frames centralizados no mesmo pivot visual.
- Pes no mesmo eixo para evitar personagem "pulando" durante walk.
- Silhueta legivel em mobile.
- Arma equipada deve ser reconhecivel em idle e shoot.

Arquivos futuros sugeridos:

```text
system/frontend/src/assets/characters/ragnar/ragnar_spritesheet.png
system/frontend/src/assets/characters/ragnar/ragnar_spritesheet.json
system/frontend/src/assets/characters/ragnar/ragnar_portrait.png
```

JSON recomendado:

```json
{
  "frameWidth": 128,
  "frameHeight": 128,
  "pivot": { "x": 64, "y": 102 },
  "animations": {
    "idle_front": { "start": 0, "end": 3, "fps": 6, "repeat": -1 },
    "walk_front": { "start": 16, "end": 23, "fps": 10, "repeat": -1 },
    "shoot_right": { "start": 96, "end": 103, "fps": 12, "repeat": 0 }
  }
}
```

## 7. Regras para Phaser

- O hub deve usar o personagem com animacoes `front`, `back`, `left`, `right`.
- O combate deve usar principalmente `left`, `right`, `aim`, `shoot`, `hit`, `fall` e `defeat`.
- O personagem deve trocar de animacao conforme input:
  - seta cima: `walk_back`
  - seta baixo: `walk_front`
  - seta esquerda: `walk_left`
  - seta direita: `walk_right`
  - parado: idle da ultima direcao
- Hitbox de movimento nao deve depender do tamanho inteiro do sprite, mas da area dos pes.
