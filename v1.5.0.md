# Spec de Implementação — v1.5.0

> Modificadores de Mapa, Sistema Visual de Personagens/Equipamentos, HUD Reformulado e Unificação de Controles

---

## 1. Resumo

Esta versão foca em três eixos principais:

1. **Sistema de modificadores de mapa** — objetos temporários que aplicam bônus ao projétil ao ser atravessados.
2. **Sistema visual de personagem composto** — imagem base por raça + layers de equipamento ao estilo DDTank, com animações por estado de gameplay.
3. **HUD reformulado** — proporcional à tela, barras visuais, hotkeys para consumíveis/modificadores, timer de turno com auto-disparo, display de vento estilo Gunbound, e controles unificados entre todos os modos de batalha.

---

## 2. Pedido Original

**Modificadores de Mapa:** conforme especificado em `v1.5.0.md` — objetos no mapa que concedem efeitos ao projétil ao ser atravessados; surgem aleatoriamente; desaparecem após um uso; disponíveis por até 3 rodadas gerais.

**Sistema de Personagem:**
- Imagem base por raça com roupa padrão simples
- Itens equipados refletem visualmente sobre o personagem (estilo DDTank)
- Assets criados a partir de itens de exemplo, adaptados ao ângulo/posição correto
- Animações por estado: idle, andar, cair, atirar, sofrer dano, morrer, preparar disparo, crítico
- Animações com poucos frames repetidos (ex.: andar = 4–6 frames em loop)

**HUD e Controles:**
- Todos os cenários de luta (PvP, dungeon, academy) devem usar os mesmos controles, física, modificadores e consumíveis
- Consumíveis: hotkeys Q, W, E, R, T com indicação visual no HUD
- Modificadores: hotkeys numéricas 1–5 com indicação visual no HUD
- Tamanho dos elementos proporcional ao tamanho da tela
- Barras de HP e estamina com visual de jogo
- Timer de turno: 20 segundos; para ao iniciar o acionamento de força; auto-disparo ao atingir 100% de força
- Display de vento inspirado no Gunbound
- Ângulo + barra de força + botão de atirar ocupando a largura total do jogo

---

## 3. Problema a Resolver

- Personagens são representados por sprites simples sem equipamento refletido visualmente, quebrando a identidade visual do jogo.
- Cada modo de batalha (PvP, dungeon, academy) pode ter diferenças de comportamento, consumíveis e controles — isso precisa ser unificado.
- O HUD atual é minimalista: texto simples sem barras, sem hotkeys visíveis, elementos muito pequenos em monitores grandes.
- Não existe timer de turno — jogadores podem demorar indefinidamente.
- O display de vento é apenas texto, sem identidade visual.

---

## 4. Objetivo da Implementação

- Personagens com visual composto e animado, refletindo cada item equipado.
- Pipeline de criação de assets completamente detalhado, incluindo etapas de uso de IA generativa.
- HUD refeito com proporções relativas à tela, barras animadas e hotkeys visíveis.
- Timer de turno de 20s com auto-disparo ao 100%.
- Display de vento visual, Gunbound-inspired.
- Controles, física e itens identicos entre todos os modos de batalha.
- Modificadores de mapa funcionando com lógica e visual de cada tipo.

## 6. Pesquisa e Referências

### O que foi pesquisado

- Sistema de sprites compostos em jogos 2D (DDTank, MapleStory, Gunbound, League of Legends)
- Spritesheets e atlases no Phaser 3
- Sistemas de HUD proporcional em jogos de navegador
- Timers de turno em jogos baseados em turnos
- Display de vento em jogos de artilharia (Gunbound, Worms)
- Pipelines de criação de assets com IA generativa (Midjourney, DALL-E 3, Stable Diffusion)
- Layered sprite composition no Phaser 3

### Pontos relevantes encontrados

- **DDTank**: cada slot de equipamento é uma imagem separada desenhada sobre o personagem na ordem correta (corpo → armadura → arma → capacete → acessórios). Cada item tem um ponto de ancoragem e ângulo definido por slot.
- **Phaser 3**: suporta `RenderTexture.draw()` para composição de sprites em tempo real, e `Phaser.GameObjects.Container` para agrupar layers com hierarquia de profundidade.
- **Spritesheet de animação**: Phaser usa `scene.anims.create()` com `frameRate` e `repeat: -1` para loops. Frames podem ser muito poucos (4–8) para economizar memória.
- **HUD proporcional**: calcular posições e tamanhos como percentual de `scene.scale.width` / `scene.scale.height`, recalcular no evento `resize`.
- **Wind display (Gunbound)**: barra horizontal com seta indicando direção e intensidade; fundo escuro semitransparente, seta colorida (azul = fraco, amarelo = médio, vermelho = forte), posicionada no topo central.
- **Timer de turno**: contagem regressiva visível; pausa quando jogador inicia acionamento de força (pressionou espaço/botão); auto-disparo ao atingir 100%.

### O que será aproveitado

- Abordagem de layers com `Container` hierárquico no Phaser 3 para composição visual.
- Formato de spritesheet com atlas JSON para animações.
- Percentuais de `scene.scale` para HUD responsivo.
- Conceito de barra de vento do Gunbound adaptado ao universo Rune Wars.
- Pipeline de IA para geração de assets base + pós-edição manual.

### O que foi descartado e por quê

- Composição em tempo real via `RenderTexture` (muito complexo para animar): usaremos `Container` com sprites separados atualizados por frame de animação.
- Assets 3D renderizados em 2D: mantém o estilo 2D HD cartoon definido na diretriz de arte.

## 10. Regras de Negócio

### 10.1 Modificadores de Mapa

1. A cada rodada geral, há chance de spawnar 1–2 modificadores em posições aleatórias acima do nível dos personagens.
2. Um modificador só pode ser ativado quando o projétil passa pela sua área (raio de 20px).
3. Ao ser ativado, aplica o efeito ao projétil e desaparece imediatamente.
4. Cada modificador desaparece após 3 rodadas gerais, mesmo que não ativado.
5. O projétil não é bloqueado pelo modificador — ele atravessa.
6. Não podem spawnar sobre terreno sólido nem fora dos limites do mapa.

### 10.2 Personagem Composto

1. Cada personagem tem uma imagem base por raça (Human, Dwarf, Elf) com roupa neutra simples.
2. Cada slot de equipamento (arma, armadura, capacete, botas, item secundário, anel, colar, brinco, pulseira) tem um layer visual com posição e ângulo pré-definidos para cada raça.
3. Se o slot estiver vazio, o layer correspondente não é exibido.
4. A ordem de renderização dos layers define qual item aparece na frente.

### 10.3 Animações

1. O estado de animação muda conforme o estado de gameplay do personagem.
2. Ao estar em idle: animação idle em loop.
3. Ao se mover: animação walk em loop.
4. Ao cair: frame de fall mantido até pousar.
5. Ao iniciar charge de força: animação charge começa.
6. Ao disparar: animação shoot (1 vez), retorna para idle.
7. Ao receber dano: animação damage (1 vez), retorna para idle.
8. Ao morrer: animação die (1 vez), personagem permanece no último frame.
9. Crítico: animação especial acionada quando o tiro causa dano acima de X% do HP máximo.

### 10.4 HUD e Controles

1. Todos os modos (PvP, Dungeon, Academy) utilizam a mesma instância do HUD e os mesmos controles.
2. Cada consumível mapeado no slot 1–5 corresponde à tecla Q, W, E, R, T respectivamente.
3. Cada modificador mapeado no slot 1–5 corresponde à tecla 1, 2, 3, 4, 5.
4. O timer de turno inicia em 20 segundos no começo do turno do jogador.
5. O timer para de contar quando o jogador pressiona espaço ou clica no botão de atirar (início do charge).
6. Se a barra de força atingir 100%, o tiro é disparado automaticamente com força 100.
7. Se o timer chegar a 0 antes do charge iniciar, o turno passa automaticamente.
8. Elementos do HUD são calculados como percentual de `scene.scale.width` e `scene.scale.height`.

## 11. Fluxo do Usuário

### Fluxo de turno com novo HUD

```
[Início do turno] → Timer 20s inicia → Player controla ângulo/movimento
→ [Player pressiona espaço ou clica Atirar] → Timer para, charge inicia
→ [Barra sobe até 100% ou player solta] → Projétil é disparado
→ [Projétil passa por modificador de mapa?] → Efeito aplicado
→ [Projétil impacta] → Explosão, dano, animação de dano no alvo
→ [Fim do turno] → Turno passa
```

### Fluxo de seleção de consumível

```
[Player pressiona Q/W/E/R/T ou clica no ícone do consumível]
→ Efeito de consumível aplicado imediatamente (se aplicável no início do turno)
→ Consumível removido do slot
```

### 12.1 Layout Geral do HUD

O HUD é dividido em 4 zonas fixas, todas relativas ao tamanho do canvas:

```

│ [PLAYER BAR: HP + Stamina]    [WIND]    [ENEMY BAR]     │  ← Topo
├─────────────────────────────────────────────────────────┤

│                  [CANVAS DO JOGO]                       │
│                                                         │
├─────────────────────────────────────────────────────────┤
│ [CONSUMÍVEIS Q,W,E,R,T]   [ÂNGULO+FORÇA+ATIRAR]  [MOD] │  ← Base
└─────────────────────────────────────────────────────────┘
```

### 12.2 Barra de Personagem (HP + Estamina)

**Player (esquerda):**
- Avatar/ícone da raça do personagem (32×32px, bordado com cor do time)
- Nome do personagem (14px bold)
- Barra de HP: gradiente verde→amarelo→vermelho conforme % de HP
- Barra de estamina: azul claro, abaixo da barra de HP
- Valores numéricos ao lado das barras (ex.: `450/500`)
- Fundo semitransparente arredondado

**Inimigo (direita):**
- Mesmo layout, espelhado

**Dimensões:**
- Largura: `scene.scale.width * 0.25`
- Altura: `scene.scale.height * 0.07`
- Margem do canto: 12px

### 12.3 Display de Vento (estilo Gunbound)

Posicionado no centro-topo.

**Componentes:**
- Caixa com fundo escuro semitransparente (largura: 200px, altura: 40px), cantos arredondados
- Label "VENTO" em fonte pequena acima da caixa
- Barra horizontal com marcações: centro = sem vento; preenchimento proporcional à intensidade
  - Vento fraco (0–30%): azul
  - Vento médio (30–70%): amarelo
  - Vento forte (70–100%): vermelho
- Seta animada (tween de posição) indicando direção (← ou →)
- Valor numérico abaixo da seta (ex.: `→ 42`)
- Abaixo da caixa: último tiro do turno anterior (Força: X | Ângulo: Y°)

### 12.4 Timer de Turno

Posicionado acima do display de vento, ou integrado a ele.

- Contagem regressiva numérica grande (ex.: `15`)
- Anel circular ao redor do número preenchendo de 100% → 0% conforme tempo passa
- 20s → 10s: cor branca
- 10s → 5s: cor amarela + leve pulsação
- 5s → 0s: cor vermelha + pulsação mais rápida
- Ao iniciar charge: número para, anel congela, cor azul ("Carregando...")
- Ao disparar: anel some

### 12.5 Consumíveis (Q, W, E, R, T)

Posicionados na base esquerda do HUD.

- 5 slots em linha horizontal
- Cada slot: ícone 52×52px com bordas arredondadas, fundo escuro semitransparente
- Label do atalho abaixo do ícone (`Q`, `W`, etc.) em cor amarela
- Nome do item em tooltip ao hover
- Se slot vazio: ícone cinza com `—`
- Quantidade no canto superior direito do ícone (se stackável)
- Ao ativar: flash de seleção + efeito de uso (tween alpha)

### 12.6 Modificadores de Disparo (1, 2, 3, 4, 5)

Posicionados na base direita do HUD.

- 5 slots em linha horizontal
- Ícone 44×44px com bordas menores que consumíveis (para hierarquia visual)
- Label numérico `1`, `2`… em canto inferior esquerdo do ícone
- Ao ativar: highlight roxo/arcano no ícone

### 12.7 Controle de Ângulo + Barra de Força + Botão Atirar

Ocupa a base central do HUD em largura total.

```
[  ÂNGULO  ] [████████████████░░░░░░░░░░░░░░░] [  ATIRAR  ]
    75°          Força: 65%                     [  ESPAÇO  ]
```

- **Ângulo:** display numérico (ex.: `75°`) + setas para ajuste fino (← →)
- **Barra de força:** ocupa a maior parte da largura central; largura = `scene.scale.width * 0.4`; altura = `scene.scale.height * 0.04`; gradiente verde→amarelo→vermelho; marcações a cada 10% (ruler já existente adaptado)
- **Botão Atirar:** botão grande com label "ATIRAR" + indicação "(ESPAÇO)"; durante charge, label muda para "CARREGANDO..." e mostra percentual
- **Timer integrado:** pequeno display do timer restante dentro desta área

### 12.8 Responsividade

Todos os valores de posição e tamanho são calculados dinamicamente:

```typescript
const W = scene.scale.width;
const H = scene.scale.height;

// Exemplos:
const hudBottomY = H * 0.92;
const barWidth = W * 0.25;
const powerBarWidth = W * 0.40;
const iconSize = Math.min(W * 0.045, 60); // máx 60px
```

O HUD deve se recalcular no evento `scene.scale.on('resize', ...)`.

### 14.3 Modificadores de Mapa — Implementação

```typescript
// map-modifier.ts
export type MapModifierType =
  | 'damage_boost'    // cristal vermelho
  | 'excavation_boost' // runa flutuante
  | 'freeze'          // gelo encantado
  | 'poison'          // cristal roxo
  | 'burn'            // chama mística
  | 'vulnerability'   // totem arcano
  | 'critical'        // portal

export interface MapModifier {
  id: string;
  type: MapModifierType;
  worldX: number;
  worldY: number;
  radius: number;        // raio de ativação (padrão 20px)
  roundsLeft: number;    // desaparece ao chegar a 0
  sprite: Phaser.GameObjects.Sprite;
}
```

**Spawn:** ao fim de cada rodada geral, `MapModifierManager.trySpawn()` decide (chance configurável) se spawna 1 ou 2 modificadores em posições válidas.

**Ativação:** dentro do loop `animateAlongPath`, para cada ponto do path, verificar se o ponto está dentro do raio de qualquer modificador ativo. Se sim: aplicar efeito e destruir o modificador.

**Efeitos:**
- `damage_boost`: `baseDamage *= 1.5`
- `excavation_boost`: `excavationRadius *= 1.5`
- `freeze`: aplica status `frozen` no alvo por 1 turno (sem movimentação)
- `poison`: aplica dano por turno por 2 turnos
- `burn`: aplica dano por turno por 1 turno + reduz HP máx temporariamente
- `vulnerability`: alvo recebe +30% dano no próximo ataque
- `critical`: força dano crítico (multiplica dano por 2)

### 14.6 Animações — Implementação

Cada animação é um spritesheet PNG + atlas JSON carregado no preload:

```typescript
// Preload em battle.scene.ts
this.load.atlas('char_human', 'assets/characters/human/atlas.png', 'assets/characters/human/atlas.json');
this.load.atlas('char_dwarf', ...);
this.load.atlas('char_elf', ...);

// Definição de animações
this.anims.create({
  key: 'human_idle',
  frames: this.anims.generateFrameNames('char_human', { prefix: 'idle_', start: 0, end: 3 }),
  frameRate: 6,
  repeat: -1,
});
```

**Estados de animação:**

| Estado   | Frames | FPS | Loop                   |
| -------- | ------ | --- | ---------------------- |
| idle     | 4      | 6   | sim                    |
| walk     | 6      | 10  | sim                    |
| fall     | 1      | —   | não (frame fixo)       |
| charge   | 3      | 8   | sim (enquanto carrega) |
| shoot    | 4      | 12  | não                    |
| damage   | 3      | 12  | não                    |
| die      | 5      | 8   | não (para no último)   |
| critical | 4      | 10  | não                    |

**`CharacterAnimator` — máquina de estado:**

```typescript
export type AnimState = 'idle' | 'walk' | 'fall' | 'charge' | 'shoot' | 'damage' | 'die' | 'critical';

export class CharacterAnimator {
  private currentState: AnimState = 'idle';

  transition(newState: AnimState): void {
    if (this.currentState === 'die') return; // die é terminal
    if (this.currentState === newState) return;
    this.currentState = newState;
    this.sprite.play(`${this.race}_${newState}`);
  }
}
```

## 16. Pipeline de Criação de Assets

Esta é a seção mais detalhada da versão, pois os assets precisam ser criados antes de qualquer implementação visual.

---

### 16.1 Conceito Visual Base

**Estilo:** 2D HD cartoon fantasy premium  
**Referências:** DDTank, Gunbound, MapleStory  
**Resolução base do personagem:** 128×160px (o sprite de jogo será escalado para ~64–80px)  
**Formato de entrega:** PNG com fundo transparente + atlas JSON gerado por TexturePacker ou ferramenta equivalente

---

### 16.2 Passo 1 — Prompt Base para Imagem de Referência de Estilo

**Objetivo:** Gerar uma imagem de referência de estilo visual para alinhar com a equipe de arte antes de criar os sprites individuais.

**Ação:** Rodar o seguinte prompt no Midjourney (ou DALL-E 3 como alternativa):

```
A set of three fantasy game characters in 2D HD cartoon style, full body view, 
white background, side-facing pose ready for game spritesheet. 
Characters: Human warrior (male, medieval armor), Dwarf warrior (stocky, runic gear), 
Elf archer (slender, leaf armor). 
Style: DDTank + MapleStory + Gunbound. 
Premium cartoon, clean silhouettes, thick outlines, vibrant colors. 
No shadows on background. Pixel-perfect readability at small sizes.
--ar 3:1 --style raw --v 6
```

**Output esperado:** Imagem de referência de estilo. Não é o sprite final — é a diretriz visual.

**Validação:** Os três personagens devem ser distintos entre si e reconhecíveis em miniatura (32×40px).

## 19. Tratamento de Erros

| Situação                                  | Comportamento                                     |
| ----------------------------------------- | ------------------------------------------------- |
| Asset de item não encontrado              | Slot fica vazio silenciosamente (sem crash)       |
| Atlas de animação não carregado           | Personagem usa sprite estático base               |
| Timer expirar durante animação de disparo | Timer não inicia novo ciclo até animação terminar |
| Modificador de mapa em posição inválida   | Descartado silenciosamente no spawn               |
