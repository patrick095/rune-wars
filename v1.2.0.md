# Spec de Implementação — Rune Wars v1.2.0

---

## 1. Resumo

A v1.2.0 é a versão de preparação para testes multiplayer. Ela concentra tudo que faz o jogo ser **testável por pessoas reais**: assets visuais para todos os itens e personagens, inventário clássico estilo RPG, cofre compartilhado entre personagens, mapas novos com estratégia e escavação, barra de força funcionando corretamente, referência de último tiro, e paridade de jogabilidade entre desktop e playground.

---

## 2. Pedido Original

> "Tenho vários itens onde não existem assets para eles, preciso que crie os assets de todos esses itens, personagens, armas, etc e aplique no jogo para que fique mais viável para testes, pois vou precisar de algumas pessoas testando junto para validar multiplayer."

Itens adicionais listados no v1.2.0.md:
- Paridade de jogabilidade desktop = playground
- Renderização em tela única / canvas único
- Barra de força funcionando + linha de referência de último tiro
- 5+ mapas para até 8 players com áreas de escavação
- Inventário clássico (36 slots 6x6 + slots de equipamento ao redor do personagem)
- Todos os itens ocupam 1 slot
- Cofre (60 slots 6x10) compartilhado, com taxa fixa de retirada de item e 3% para dinheiro

---

## 3. Problema a Resolver

O jogo está tecnicamente implementado mas **não é testável por pessoas reais** porque:
- Itens não têm representação visual — jogadores não sabem o que estão usando
- A barra de força (power meter) está quebrada — mecânica central do jogo inoperante
- Não há inventário acessível durante a sessão de jogo
- Os mapas existentes (castle + plains) são insuficientes para validar estratégia multiplayer
- Desktop e playground têm comportamentos diferentes, gerando confusão nos testes
- Navegar entre telas quebra a imersão e dificulta sessões rápidas de teste

---

## 4. Objetivo da Implementação

Entregar uma build jogável e testável por beta testers, com todos os sistemas visuais e de UI necessários para que uma sessão multiplayer real possa acontecer e ser validada.

## 6. Pesquisa e Referências

### O que foi pesquisado
- Inventário estilo RPG clássico (Diablo 2, MU Online, DDTank, RuneScape)
- Power meter / force bar em jogos de artilharia (Worms, Gunbound, DDTank)
- Design de mapas para turn-based com múltiplos jogadores
- Padrões de sprites 2D para jogos de artilharia

### Pontos relevantes encontrados
- **Inventário clássico**: Diablo/MU usam grid com personagem centralizado, equipamentos ao redor em slots nomeados. Jogadores esperam esse padrão.
- **Power meter**: em Worms e Gunbound a barra cresce com botão segurado e para quando soltar — o valor do número já funciona, o problema é o componente visual (barra HTML/Canvas não atualiza)
- **Linha de referência de tiro**: Gunbound e DDTank mantêm a trajetória do último projétil em linha pontilhada ou trace ghost — ajuda calibração sem precisar memorizar
- **Mapas multiplayer**: Worms e Gunbound usam mapas com plataformas, terreno destrutível e esconderijos. Para 8 players precisa de áreas de respiro (cover natural) e múltiplos corredores
- **Cofre compartilhado**: RuneScape (bank), MU (vault), DDTank (cofre) — todos cobram taxa de retira de ouro/dinheiro, não de itens

### O que será aproveitado
- Grid 6x6 para inventário (padrão estabelecido, simples de implementar em HTML/CSS sobre canvas)
- Trajetória ghost para referência de último tiro (linha pontilhada no Phaser Graphics layer)
- Barra de força com fill animation (retângulo que cresce — rebuild simples no Phaser HUD)
- 1 slot = 1 item independente do tamanho (decisão já tomada no v1.2.0.md — simplifica drag-and-drop)

### O que foi descartado e por quê
- Itens ocupando múltiplos slots (Diablo-style 2x3): o v1.2.0.md explicita "apenas 1 slot" — simplifica UI e balanceamento
- Cofre com taxas de item (apenas para dinheiro): v1.2.0.md define taxa fixa para itens e 3% para dinheiro

## 10. Regras de Negócio

### Inventário
- RN01: Inventário tem 36 slots organizados em grid 6x6
- RN02: Cada item ocupa exatamente 1 slot, independente do tipo
- RN03: Personagem tem slots de equipamento: Mão Principal, Mão Secundária, Armadura, Capacete, Botas, Anel 1, Anel 2, Colar, Brinco, Pulseira (10 slots)
- RN04: Inventário é por personagem (não compartilhado)
- RN05: Ao entrar na partida, jogador seleciona quais itens do inventário levará

### Cofre
- RN06: Cofre tem 60 slots (6x10)
- RN07: Cofre é compartilhado entre todos os personagens de uma conta
- RN08: Retirar item do cofre cobra taxa fixa em gold (valor: **[P1 — PENDENTE]**) 
- RN09: Retirar dinheiro do cofre cobra 3% do valor retirado
- RN10: Dinheiro fica em saldo separado dos itens (não ocupa slot)
- RN11: Depositar no cofre é gratuito

### Mapas
- RN12: Mapa deve suportar de 2 a 8 spawn points
- RN13: Todo mapa battle deve ter pelo menos 1 área de terreno escavável com volume significativo
- RN14: Spawn points devem ser distribuídos para evitar spawn killing

### Barra de Força
- RN15: Barra de força cresce progressivamente enquanto o botão de disparo é pressionado
- RN16: Barra de força para no máximo ao soltar ou atingir 100%
- RN17: O valor numérico deve refletir exatamente o estado visual da barra

### Linha de Referência
- RN18: Após cada disparo, a trajetória do projétil fica visível como linha ghost pontilhada
- RN19: A linha de referência pertence apenas ao jogador que atirou (não visível para adversários)
- RN20: Sugestão: apaga ao iniciar o próprio turno seguinte **[confirmar P4]**

## 11. Fluxo do Usuário

### Fluxo de Inventário
```
Hub → Village (POI) → Tela de Personagem
  → Aba Inventário: grid 6x6 + personagem com slots de equip.
  → Drag/Click item → equipa ou move para slot
  → Aba Cofre: grid 6x10
  → Mover item inventário→cofre: gratuito
  → Mover item cofre→inventário: cobra taxa fixa [P1]
  → Sacar dinheiro: confirma valor, desconta 3%
```

### Fluxo de Entrada na Partida
```
Selecionar partida → Modal "Preparar Loadout"
  → Grid mostra inventário do personagem
  → Jogador seleciona itens que levará (max: capacidade de armas/consumíveis)
  → Confirmar → entra na sala
```

### Fluxo de Tiro com Referência
```
Turno começa → linha ghost do turno anterior visível
  → Jogador mira, vê ângulo
  → Segura botão: barra de força cresce visivelmente
  → Solta: projétil disparado, linha ghost atualiza para este tiro
  → Fim do turno: linha persiste até próximo turno deste jogador
```

## 13. Backend

### Novas Entidades

**Vault (Cofre)**
```typescript
// vault.entity.ts
@Entity()
export class Vault {
  @PrimaryGeneratedColumn('uuid') id: string;
  @ManyToOne(() => User) user: User;           // por conta, não por personagem
  @Column({ type: 'int', default: 0 }) gold: number;
  @OneToMany(() => VaultSlot, s => s.vault) slots: VaultSlot[];
}

// vault-slot.entity.ts
@Entity()
export class VaultSlot {
  @PrimaryGeneratedColumn('uuid') id: string;
  @ManyToOne(() => Vault) vault: Vault;
  @Column({ type: 'int' }) slotIndex: number;  // 0–59
  @ManyToOne(() => ItemInstance, { nullable: true }) item: ItemInstance | null;
}
```

### Novos Endpoints

| Método | Rota | Descrição |
|--------|------|-----------|
| GET | `/vault` | Retorna cofre da conta (auth) |

| POST | `/vault/deposit/gold` | Deposita gold no cofre |
| POST | `/vault/withdraw/gold` | Retira gold do cofre (cobra 3%) |

- Taxa de retirada de item: constante configurável `VAULT_ITEM_FEE` (valor: **[P1]**)

## 18. Fixes Técnicos

### Fix 1: Barra de Força (Power Meter)

**Diagnóstico**: O valor numérico (`forceValue`) é calculado corretamente mas o componente visual (provavelmente um elemento HTML/CSS sobre o canvas) não reage às mudanças durante o `mousedown`.

**Solução**: Migrar o power meter do DOM Angular para um objeto Phaser nativo:

```typescript
// power-meter-hud.ts (novo arquivo em game/hud/)
export class PowerMeterHUD {
  private bg: Phaser.GameObjects.Rectangle;
  private fill: Phaser.GameObjects.Rectangle;
  private label: Phaser.GameObjects.Text;

  constructor(scene: Phaser.Scene, x: number, y: number) {
    this.bg = scene.add.rectangle(x, y, 200, 20, 0x333333).setScrollFactor(0);
    this.fill = scene.add.rectangle(x - 100, y, 0, 20, 0x00ff88).setScrollFactor(0).setOrigin(0, 0.5);
    this.label = scene.add.text(x, y + 16, '0%', { fontSize: '12px' }).setScrollFactor(0).setOrigin(0.5);
  }

  update(force: number) { // force: 0–100
    this.fill.width = force * 2; // fill de 0 a 200px
    this.fill.setFillStyle(force > 70 ? 0xff4444 : force > 40 ? 0xffaa00 : 0x00ff88);
    this.label.setText(`${Math.round(force)}%`);
  }
}
```

### Fix 2: Linha de Referência do Último Tiro (Ghost Trace)

```typescript
// ghost-trace.ts (novo arquivo em game/hud/)
export class GhostTrace {
  private graphics: Phaser.GameObjects.Graphics;
  private lastPoints: {x: number, y: number}[] = [];

  constructor(scene: Phaser.Scene) {
    this.graphics = scene.add.graphics();
  }

  recordShot(points: {x: number, y: number}[]) {
    this.lastPoints = points;
    this.redraw();
  }

  private redraw() {
    this.graphics.clear();
    if (this.lastPoints.length < 2) return;
    this.graphics.lineStyle(2, 0xffffff, 0.4);
    // linha pontilhada: segmentos alternados
    for (let i = 0; i < this.lastPoints.length - 1; i += 2) {
      this.graphics.strokeLineShape(new Phaser.Geom.Line(
        this.lastPoints[i].x, this.lastPoints[i].y,
        this.lastPoints[i + 1].x, this.lastPoints[i + 1].y
      ));
    }
  }

  clear() {
    this.graphics.clear();
    this.lastPoints = [];
  }
}
```

- Inventário: já protegido, validar `characterId` pertence ao usuário logado
- Taxa de retirada: calculada **exclusivamente no backend** — frontend não pode enviar valor calculado

## 21. Logs e Monitoramento

### Logs Importantes
- `VAULT_WITHDRAW_ITEM`: quem, qual item, qual taxa cobrada
- `VAULT_WITHDRAW_GOLD`: quem, quanto, taxa cobrada
- `VAULT_INSUFFICIENT_GOLD`: tentativa de retirada sem saldo

### Eventos de Monitoramento
- Contagem de cofres criados (gauge)
- Volume de gold movimentado via cofre (métrica de economia)

## 22. Tratamento de Erros

| Cenário | Mensagem para o Usuário | Ação do Sistema |
|---------|------------------------|-----------------|
| Inventário cheio (36/36) | "Inventário cheio. Libere espaço para mover este item." | Bloquear ação |
| Cofre cheio (60/60) | "Cofre cheio. Não há espaço disponível." | Bloquear ação |
| Gold insuficiente para taxa | "Gold insuficiente. Precisa de X gold para esta operação." | Bloquear ação |
| Erro de rede | "Erro ao sincronizar. Tente novamente." | Toast de erro + retry automático |
| Item equip no slot errado | "Este item não pode ser equipado neste slot." | Highlight do slot correto |
